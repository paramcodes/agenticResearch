## Gotchas (do not re-learn these)

1. **Bun `--filter` needs `=`**: `bun --filter <pkg>` matches nothing;
   always `bun --filter=<pkg>`. This bit the root `db:*` scripts, the api
   Dockerfile, the web Dockerfile, and the compose boot command.
2. **Sibling `tsconfig extends` needs an explicit dep**: Bun isolates
   `node_modules`, so `@repo/typescript-config` must be a real
   (`workspace:*`) devDependency in every package, not just present at root.
   Add via manual `package.json` edit — `bun add` hits the npm registry (404).
3. **TS 7 does not auto-include `@types`**: `process` was unknown in
   `@repo/db` despite `@types/node` installed. Fix: explicit
   `"types": ["node"]` in tsconfig (api already had it).
4. **`import Redis from "ioredis"` fails under NodeNext+TS7** (namespace /
   not-constructable errors). Use `import { Redis } from "ioredis"`.
5. **Express `const router = Router()` trips TS2883** (non-portable inferred
   type). Annotate: `const router: Router = Router()`.
6. **Prisma client is NOT generated by `migrate deploy`**: the api container
   crashed with "@prisma/client did not initialize yet". Fix does two places:
   `RUN bun --filter=@repo/db run db:generate` in the api Dockerfile (offline
   safe) plus `db:generate && db:deploy` in the compose boot command.
7. **WS race — attach `message` handler before async auth**: a client sending
   on `open` lost its first frame because the listener was registered after
   token DB checks. `apps/api/src/ws.ts` now queues pre-auth frames and
   flushes after verification. Any Step-3 streaming code must keep this shape.
8. **`bunx --filter=@repo/db prisma` installed the wrong Prisma major**
   (v8-rc, `migrate` unknown). Inside containers/images always use the
   package-local binary or `bun --filter=@repo/db run <script>`.
9. **Initial migration was made offline** via
   `prisma migrate diff --from-empty --to-schema-datamodel … --script`
   (no DB needed), plus a hand-written `migration_lock.toml`.
10. **This machine's docker needs `DOCKER_CONFIG=/tmp/empty-docker`**
    (config.json points at missing `docker-credential-desktop`). Repo files are
    fine — it is a host quirk. `docker compose config` is the cheap check.
11. **Vite `VITE_*` is build-time**: changing `VITE_API_URL` /
    `VITE_GOOGLE_CLIENT_ID` requires `docker compose up --build` (noted in
    README + AGENTS.md).
12. **Seed runs on Bun, not tsx** (`db:seed": "bun prisma/seed.ts"`), and the
    seed imports `../src/index.js` (NodeNext-style) which Bun maps to `.ts`.

## Decisions worth keeping

- Redis is **best-effort** (lazy connect, all helpers swallow errors): verified
  the api serves auth/CRUD with the redis container stopped. Do not add hard
  startup dependency on it.
- Google auth without `GOOGLE_CLIENT_ID` decodes instead of verifying, gated
  by `ALLOW_INSECURE_GOOGLE_DEV` (default true locally, must be false in prod
  — api throws without `JWT_SECRET` in production already).
- Agent page uses **HTTP in Step 2**; `/ws` speaks the same logical protocol
  with coarse progress so Step 3 only swaps the transport + streams tokens.
- No commits were made during implementation (history: repo has no HEAD;
  pre-existing deletions of template `apps/docs` etc. are untouched).
